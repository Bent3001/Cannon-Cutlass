## Bearbeitung

Codex · Deckspeicher · CC-705 · 2026-11-18

## Ziel

Spieler sollen vorbereitete Flotten behalten und vor dem nächsten Match gezielt wechseln können.

## Umfang

Lege browserlokale Deckdaten mit stabiler Kennung, Name, Schiffsliste und aktivem Deck fest. Stelle die Datenoperationen für Anlegen, Kopieren, Umbenennen, Speichern, Löschen und Aktivieren bereit. CC-706 bindet sie im Menü an und übergibt das aktive Deck an die Aufstellung. Nutze für den aktuellen Stand die vorhandene Standardflotte. Individuelle Schiffstypen folgen mit CC-305 und CC-306.

## Abnahmekriterien

- [x] Mindestens zwei benannte Decks und die aktive Auswahl bleiben nach Neuladen erhalten.
- [x] Bearbeiten oder Duplizieren eines Decks verändert andere Decks nicht. Der Datenspeicher kann eine eigenständige Kopie des aktiven Decks für eine neue Aufstellung liefern.
- [x] Der Datenspeicher legt einen reproduzierbaren Fallback fest, wenn das aktive Deck gelöscht wird. Löschung mit einem verbleibenden Deck, Löschung des letzten Decks und unbrauchbare gespeicherte Daten ergeben jeweils eine gültige aktive Auswahl. Bei einem frischen Profil ist das Standarddeck aktiv.
- [x] Die Datenstruktur kann später Schiffskennungen aus dem Katalog speichern.

## Umsetzung

Das [Speichermodul](../../crates/web/assets/deck-store.js) speichert Decks und aktive Kennung zusammen als versioniertes JSON unter `cannon-cutlass.decks` in `localStorage`. Axum und der statische Export liefern das Modul über denselben Asset-Pfad aus. Die Standardflotte übernimmt ihre Schiffskennungen aus der Maud-Ansicht. Die gespeicherte Schiffsliste besteht aus Zeichenketten und kann später Katalogkennungen einschließlich mehrfach ausgerüsteter Schiffstypen aufnehmen.

Neue und duplizierte Decks werden ans Ende der Liste gesetzt. Die Auswahl ändert sich durch explizites Aktivieren. Fehlt das aktive Deck oder wird es gelöscht, rückt das erste vorhandene Deck nach. Bei leerem oder unbrauchbarem Speicher gilt die Standardflotte. `getActiveDeck()` liefert eine eigenständige Kopie für die Aufstellung.

### Manuell nachprüfen

Die WebApp über `just start` oder als statischen Export in einem frischen Browserprofil öffnen. Der folgende Code öffnet den Speicher in der Entwicklerkonsole.

```js
const { openDeckStore } = await import("./assets/deck-store.js");
const ships = [...document.querySelectorAll("[data-deck-ship]")].map((button) => button.dataset.deckShip);
const store = openDeckStore(ships);
```

`store.getActiveDeck()` liefert anfangs die Standardflotte. Mit `const north = store.create("Nordflotte")`, `const south = store.duplicate(north, "Südflotte")` und `store.activate(south)` zwei Decks vorbereiten. Nach dem Neuladen den Speicher erneut öffnen und mit `store.list()` beide Namen und mit `store.getActiveDeck()` die Südflotte prüfen. Beim Löschen der Südflotte wird die Standardflotte aktiv. Beim Löschen der Standardflotte rückt die Nordflotte nach. Beim Löschen der Nordflotte wird die Standardflotte wiederhergestellt. Zum Prüfen der Kopie die Liste `store.getActiveDeck().ships` in einer lokalen Variablen ändern und das aktive Deck erneut abfragen.

Löschen eines inaktiven Decks ließ die aktive Auswahl bestehen. Operationen mit unbekannten Kennungen, einem leeren Namen oder einer lückenhaften Schiffsliste wurden ohne Änderung am Speicher zurückgewiesen.
